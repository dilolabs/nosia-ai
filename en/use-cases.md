<section id="developer-tooling" class="description">
  <div class="container">
    <h2>Developer tooling with an OpenAI-compatible API</h2>
    <p><strong>The need:</strong> connect an existing application to a Nosia instance. <strong>With Nosia:</strong> configure the OpenAI-compatible application programming interface (API) and an access token. Test the functions your application relies on: compatibility does not mean full parity with every OpenAI service.</p>

<section id="mcp-integration" class="description">
  <div class="container">
    <h2>Connecting AI to your internal tools (MCP)</h2>
    <p><strong>The need:</strong> use information from another tool. <strong>With Nosia:</strong> configure a server supporting the Model Context Protocol (MCP), an open protocol linking AI to tools and data sources. Review permissions, test the connection and enable it for the conversation. Available actions and data sent depend on the server and external service you choose.</p>
    <a href="{{ '/en/' | relative_url }}#features" class="btn btn-secondary">See features</a>
  </div>

Self-hosting alone does not guarantee compliance: access, security, backups, models and external connections require appropriate assessment and configuration.</p>
